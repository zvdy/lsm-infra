## What was confirmed

- **ECR repository:** `IMMUTABLE` tags, `scanOnPush: true`, `KMS` encryption.
- **Lifecycle policy:** untagged images expire after 7 days.
- **KMS key:** customer-managed, enabled, automatic rotation on.
- **OIDC provider:** `token.actions.githubusercontent.com` created.
- **Push role:** trust restricted to `aud=sts.amazonaws.com` and
  `sub=repo:zvdy/lsm-rust:ref:refs/tags/v*`; permissions are the ECR push
  actions only, scoped to this repository (plus `GetAuthorizationToken`).
- **Push:** the `lsm-rust` image (built from `main`) pushed successfully.
- **Immutability:** pushing different content to the same tag was rejected:
  `The image tag '0.1.0-verify' already exists ... because the tag is immutable.`

## What was not confirmed

- **Vulnerability scan results.** `describe-image-scan-findings` returned
  `ScanNotFoundException` within the ~30 s I waited. The pushed artifact is an
  OCI index (image plus provenance attestation), which may not be scanned on
  push. This is unresolved; CI scans the image with Trivy regardless.
- **OIDC role assumption from GitHub Actions.** The role and its trust policy
  exist, but no workflow assumed it. That needs a tagged release.

## Cleanup and cost

- The pushed images were deleted first (ECR refuses to delete a non-empty
  repository), then `terraform destroy` removed all 7 resources; state is empty.
- The KMS key cannot be deleted immediately. It is in `PendingDeletion` until
  **2026-10-17** (the 7-day minimum, set by `kms_deletion_window_days`; the
  default is 30). As I understand AWS KMS pricing, keys pending deletion are not
  billed; confirm on the next bill.
- Expected cost of the run: well under $1 (a few hours of one KMS key, one
  small image stored for minutes).

## Reproduce

```sh
cd aws-ecr
terraform init
terraform plan -var kms_deletion_window_days=7 -out=tfplan
terraform apply tfplan
# ...verify...
terraform destroy -var kms_deletion_window_days=7   # empty the repo first
```
